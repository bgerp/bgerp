AWS SDK for PHP в backup
========================

Избор на версии
---------------
- BACKUP_AWS_VERSION има default 3.272.2, както досегашният install().
- Добавени са 3.337.3 (PHP >=7.2.5, тестван с PHP 7.4/8.2) и 3.402.3
  (PHP >=8.2). Версията на bgERP Setup остава 0.1.
- BACKUP_STORAGE_TYPE остава local по подразбиране. Пътища, credentials,
  кофи, регион eu-west-1, периоди, cron описания и архивни формати не се сменят.
- core_Packs показва стандартна грешка към полето при избор на 3.402.3
  под PHP 7.4. Проверка има и преди Composer install и преди създаване на
  S3 клиента, без зареждане на несъвместимия SDK.
- SDK се инсталира чрез съществуващия core_Composer само при избрано
  amazon съхранение. Локалното архивиране не се нуждае от AWS във vendor.
  Използва се точната избрана версия, което допуска и понижаване при
  съвместими ограничения на останалите Composer зависимости.
- Не се добавят отделни производствени Composer проекти или SDK файлове
  в Git; не се променя core_Composer. Не се изпълнява общ composer update.
- checkConfig() проверява наличната версия при S3 съхранение и показва
  указание за инициализиране, ако тя липсва/е различна.

Поправки на адаптера
-------------------
- Липсващ Composer/SDK води до ясно expect съобщение.
- putFile() отваря файла с rb вместо r+; не е нужно право за запис върху
  източника. Потокът се затваря във finally, включително при изключение.
  Липсващ, празен или невалиден файлов път връща false.
- Запазени са булевите резултати на getFile/putFile/removeFile и прехвърлянето
  на core_exception_Redirect. Не се променят S3 key-овете и SaveAs поведението.
- За съзнателно избрания PHP 7.4 клон се използва официалната опция
  suppress_php_deprecation_warning, без да се изключват PHP грешките.

3.402.3 е стабилен release от 2026-10-28; той е по-нов от първоначалния план.
Добавя актуални AWS API модели и поправя загубата на оригиналното изключение
при определени STS грешки в AssumeRoleCredentialProvider. От 3.402.0
минимумът е PHP 8.2. 3.337.3 е съвместимият исторически клон за PHP 7.4;
съвместимостта му не означава текуща upstream поддръжка на PHP 7.4.

SDK запазва Apache-2.0. aws/aws-crt-php (тестван 1.2.7) също е Apache-2.0;
mtdowling/jmespath.php (2.9.2) е MIT. Лицензите се доставят с Composer.
Останалите зависимости са Guzzle, PSR интерфейсите и за новия SDK Symfony
Filesystem. Не е необходимо да се преминава към Guzzle 8 за новия SDK.

Проверки
--------
- PHP 7.4.33: по 26 проверки за 3.272.2 и 3.337.3; 5 проверки, че
  3.402.3 се отказва преди autoload/Composer.
- PHP 8.2.34: по 26 проверки за трите версии.
- Реален SDK, сериализиране, Signature V4 и разчитане на HTTP резултати,
  реалните методи на backup_Amazon, синтетичен HTTP транспорт без мрежа:
  PUT/GET/DELETE, кирилски имена с интервали, двоични байтове, празен файл,
  8 MB файл със SHA-256 сравнение, 403/404, липсващ/невалиден източник и
  файл само за четене. Преди поправката последният тест се проваляше.
- Browser: 17 S3 проверки на съвместимите комбинации PHP/SDK. Проверени
  са стандартният отказ на PHP 7.4, успешен избор на 3.402.3 през PHP 8.2,
  връщане към 3.337.3 и непроменен тип local през core_Packs.
- Допълнителни S3 тестове с текущите общи Guzzle/PSR зависимости:
  Guzzle 7.9.2, PSR7 2.7.0 и Promises 2.0.4. Тествани са и изолирано
  разрешените по-нови зависимости, включително Guzzle 8 за 3.402.3.
- Сухите Composer проби върху копие на общия lock за двете нови версии
  добавят само SDK, CRT и JmesPath: 0 updates и 0 removals.
- Общият производствен Composer не е променян за AWS, защото S3 не е
  избрано. Версията е настроена чрез UI; пакетът остава неактивен.
- PHP lint и redirect-catch проверка. Няма други AWS потребители в
  прегледаните частни пакети.

Повторение от корена на bgERP:
php backup/tests/awsVersions.php /path/to/vendor/autoload.php 3.337.3
php backup/tests/awsVersions.php /path/to/vendor/autoload.php 3.402.3
Първият аргумент е autoloader от тестова Composer инсталация на избрания SDK.
Тестът не използва реални AWS ключове, кофи или архиви.

Ограничения и инсталационни стъпки
--------------------------------
Не са изпълнявани реални S3 заявки, mysqldump, възстановяване на база,
binlog архивиране, cron регистрация или изтриване на действителни архиви.
Синтетичният транспорт проверява клиентското API, но не доказва AWS IAM
права, достъпност, регион/политики на кофа, quota или реална мрежова скорост.
Локалната backup конфигурация остава неактивна и показва досегашния проблем
с липсващи права за локалния storage; това не е настройвано като част от SDK.

При реално включване на S3 се избира SDK, задават се credentials/кофа и
се инициализира backup по стандартния ред. Съществуващият пълен setup
проверява storage/MySQL и регистрира cron само при успешна конфигурация.
След инсталиране се използва нова PHP заявка. Една обща Composer инсталация
не може едновременно да зареди две AWS версии. Ако се ползва и от PHP 7.4,
тя трябва да остане на съвместимия SDK, а не на 3.402.3.
При конфликт с други зависимости Composer трябва да върне грешка; не
използвайте широко обновяване на общите зависимости само за понижаване.
