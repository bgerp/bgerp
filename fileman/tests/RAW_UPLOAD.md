# Качване на двоични части

`fileman_Upload` използва JSON за началните метаданни и
`application/octet-stream` за частите. Настройката `FILEMAN_USE_CHUNK_UPLOAD`
и контролерът `fileman_Upload2` са премахнати. Размерът на частите продължава
да се задава чрез `FILEMAN_CHUNK_SIZE`.

Общият транспорт `fileman_ChunkedUpload` проверява размера на всяка част,
целия файл и SHA-256. Качването е обвързано с потребителя, браузъра и
предназначението му. Повторение на последната заявка връща запазения резултат.
Временните данни изтичат след един час и се почистват чрез `core_CallOnTime`.
Необходим е работещият стандартен cron на приложението.

SHA-256 използва Web Crypto, когато е достъпен, и включената локална JS
реализация в останалите случаи. Обикновеното качване работи и по HTTP.
PWA продължава да изисква среда, която позволява Service Worker.

## PWA и внедряване

Native Web Share Target запазва `multipart/form-data` в манифеста.
Service Worker приема тази заявка вътре в браузъра и изпраща към PHP само
JSON и двоични части. Без актуален worker директният POST към
`pwa_Share/Target` не обработва файлове.

1. Инсталирайте кода и инициализирайте пакета `pwa`, за да бъдат публикувани
   новият worker и включеният SHA код за активните домейни. При собствен
   `serviceworker.js` приложете същата обработка и SHA зависимостта в него.
2. Обновете отворените диалози за качване и PWA приложението. Проверете, че
   актуалният worker е активен. Старите адреси `fileman_Upload2` вече не съществуват.
3. Проверете качването и PWA споделянето в използваните браузъри и устройства.
4. Приложете забраната за multipart преди PHP в действителната конфигурация
   на reverse proxy/web server. Промените в `_docs` са шаблони и сами по себе си
   не променят работещите сървъри. Проверете всички активни частни интеграции.

За HAProxy правилото за multipart вече може да няма изключения по upload path:

```haproxy
http-request deny deny_status 400 if { req.hdr_cnt(content-type) gt 1 }
acl is_multipart req.fhdr(content-type) -i -m sub multipart
http-request deny deny_status 403 if is_multipart
```

Проверете синтаксиса с версията на HAProxy на съответния сървър преди reload.
Apache шаблоните в `_docs` съдържат аналогична забрана чрез `mod_rewrite`;
тя действа само когато съответната конфигурация е заредена и разрешена.
Лимитът на request body трябва да допуска поне `FILEMAN_CHUNK_SIZE`.
Смяната на транспорта не заменя обновяването на PHP и сървърните настройки.

## Автоматични проверки

От корена на хранилището, с Node.js 18+ и PHP 7.4 или 8.2:

```sh
node fileman/tests/raw-upload.mjs
node pwa/tests/raw-share.mjs
```

Първият тест стартира изолиран PHP HTTP сървър и използва временна директория,
без конфигурацията или базата на приложението. `PHP_BINARY` избира PHP бинарния
файл. Незадължителният URL аргумент позволява предварително стартиран fixture
сървър, чиято директория е зададена с `RAW_UPLOAD_TEST_DIR`.

Проверяват се SHA-256 с/без Web Crypto, няколко файла, празен файл, повторени
и разместени части, окончателен retry, размери, SHA несъответствие,
обвързване с потребител/браузър, невалидни индекси и отказ на multipart.
PWA тестът изпълнява worker кода с изолирани HTTP/client заместители и проверява
прогреса, повторен опит, подновяване на token при бавно хеширане, текст и връзки.

## Проверка в браузър

- От нова бележка отворете "Файл" в редактора. Изберете два тестови файла,
  поне единият по-голям от размера на частта. Качете ги и проверете отделния
  прогрес, двата успешни резултата и прикачването в редактора.
- Повторете с поле за един файл, празен файл, неразрешено разширение и файл
  над лимита на кофата. Отказаните файлове не трябва да се запишат.
- Проверете качване по HTTP на адрес без secure-context изключение.
- От инсталираната PWA споделете два файла, после само текст и връзка.
  Проверете прогреса и крайния екран. Повторете с излязъл потребител и вход
  след споделянето. Native Android share UI се проверява на реално устройство.
- В Network трябва да има JSON начало и `application/octet-stream` части,
  без multipart POST към сървъра. При активна server забрана обикновеното
  качване и PWA споделянето трябва да продължат да работят.
