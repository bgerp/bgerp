# jQuery UI

## Версии и настройки

Добавена е официалната jQuery UI 1.14.2 в отделна директория. Версиите 1.8.2,
1.11.3, 1.12.1 и 1.13.3 са запазени без промяна. Глобалният default остава
`JQUERYUI_VERSION = 1.12.1`; default за jQuery остава `1.11.2`.

Новата версия се избира през `core_Packs`, настройки на пакета `jqueryui`.
Изборът засяга само текущата инсталация. Адаптерът работи с PHP 7.4 и 8.2.
Библиотеката е JavaScript и не добавя PHP или Composer зависимости.

jQuery UI 1.14.2 е проверена от upstream с jQuery 1.12.4, 2.2.4, 3.6.4, 3.7.1
и 4.0.0. Проверката `checkConfig()` показва стандартна setup диагностика при
по-стара неподдържана комбинация, включително глобалния jQuery default 1.11.2.
За новата UI версия използвайте jQuery 3.7.1 или 4.0.0. Изборът на jQuery не се
променя автоматично. Диагностиката не забранява записването на настройката.

Спрямо 1.12.1 има поддръжка на съвременен jQuery, поправки в обработката на HTML,
позиционирането и календара. В 1.14.2 са поправени и табове с Unicode
идентификатори и е премахната зависимостта от Mousewheel. Това е обновяване на
съвместимостта и поддръжката, а не нов набор от контроли или тема.

Серия 1.14 изключва по подразбиране съвместимостта с API от 1.11. Адаптерът
зарежда `js/compat.js` преди новата библиотека, за да запази използваното старо
API, включително `button({icons: ...})` и `buttonset()`. `getJsFiles()` определя
общия ред за обикновено зареждане и `getCommonJs()` на compactor. Старите версии
не зареждат този допълнителен файл. CDN настройките и локалният fallback са
запазени; при външен CDN URL администраторът трябва да съгласува версията и SRI.

При активен `compactor` и смяна на версия инициализирайте и пакета `compactor`
през `core_Packs`, за да обнови записания си списък от JS/CSS пътища. След
презареждане проверете, че се зарежда само избраната UI версия.

## Повторими проверки

От корена на хранилището генерирайте самостоятелни страници:

```sh
php jqueryui/tests/render.php /tmp/jqueryui-check/new 1.14.2 4.0.0 new compact
php jqueryui/tests/render.php /tmp/jqueryui-check/legacy 1.14.2 3.7.1 legacy plain
php jqueryui/tests/render.php /tmp/jqueryui-check/defaults 1.12.1 1.11.2 new compact
php jqueryui/tests/render.php /tmp/jqueryui-check/old-ui 1.12.1 4.0.0 new compact
python3 -m http.server 9004 --bind 127.0.0.1 --directory /tmp/jqueryui-check
```

Повторете генерирането с PHP 8.2 в отделни изходни поддиректории. Отворете
генерираните страници в браузър и натиснете `Run regression tests`. Очакваният
краен резултат за всяка е `ALL 25 CHECKS PASSED`.

CLI проверява defaults, зареждането на четирите стари версии, диагностиката за
jQuery и реда при CDN. Страниците използват реалните адаптери за jqueryui,
minify и compactor с изолирани framework/SBF заместители, без база данни.
`new` означава JShrink 1.8.1 и CSSmin 4.1.1; `legacy` използва старите минификатори.

Резултат от проверките на 28.10.2026: четирите комбинации преминаха на PHP
7.4.33 и 8.2.34, общо 8 страници и 200 успешни браузърни проверки. Покрити са
диалог и overlay, кирилица, CSS и зареждане на иконите след compactor, старото
API на бутоните, autocomplete с асинхронен източник, високосна дата, календар,
табове, drag/drop, ограничаване на влаченето, sortable и 500 динамични реда.
Преминаха PHP lint и проверката за redirect catches.

При сравнението 1.12.1 не отваря табове с кирилица в идентификаторите, а 1.14.2
ги отваря. Тестът за старата версия използва ASCII идентификатори, за да
разграничи съществуващото ограничение от регресия.

За реална интеграционна проверка използвайте тестова POS каса и празна тестова
бележка от собствената инсталация. Отворете помощта с F1, преместете и затворете
диалога; с Ctrl+M отворете клавиатурата, изберете BG и въведете кирилица.
Превключете 1.12.1 -> 1.14.2 -> 1.12.1 -> 1.14.2 през настройките и презареждайте
терминала. Диалозите трябва да работят и да се зарежда само избраната библиотека.
Този сценарий премина в реалното приложение на PHP 7.4 и 8.2; местенето на
диалога беше проверено на PHP 7.4. Не е нужна продажба, плащане или печат.

Ограничения: браузърните проверки са в Chromium. Асинхронният autocomplete и
drag/drop в самостоятелната страница са със синтетични данни и събития;
sortable проверява API и реда след преместване в DOM. Не са проверявани всички
бизнес екрани, външни куриерски услуги, реален CDN или всички браузъри.
Поддръжката на стари IE/EdgeHTML браузъри е премахната upstream в серия 1.14.
