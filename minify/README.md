# Минифициране на CSS и JavaScript

Проверени официални версии към 27.10.2026:

| Библиотека | Директория | Издание | Лиценз |
| --- | --- | --- | --- |
| CSSMin 4.1.1 | `cssmin/4.1.1/` | [v4.1.1, 15.01.2018](https://github.com/tubalmartin/YUI-CSS-compressor-PHP-port/tree/v4.1.1) | BSD-3-Clause |
| JShrink 1.8.1 | `jshrink/1.8.1/` | [v1.8.1, 20.11.2025](https://github.com/tedious/JShrink/releases/tag/v1.8.1) | BSD-3-Clause |

CSSMin 4.1.1 е последният стабилен таг на използваната CSS библиотека. JShrink е
добавен като отделен JS minifier. Досегашните реализации в `Css.class.php` и
`Js.class.php` остават налични, включително директните им методи `make()` и `min()`.

## Избор и зависимости

Двете нови настройки са в "Система -> Пакети -> minify -> Настройки":

```php
MINIFY_CSS_VERSION = 'legacy'
MINIFY_JS_VERSION = 'legacy'
```

Това са глобалните defaults. Инсталации без изричен избор продължават със стария код.
Изборът на `4.1.1` и `jshrink-1.8.1` се записва само в настройките на съответната
инсталация. Няма миграция или промяна на `$version` на пакета.

Стандартният запис на настройките инициализира minify. Съществуващият `install()`
премахва старите генерирани CSS/JS файлове от SBF, за да се създадат с избрания
minifier. При връщане към старите версии се използва същият механизъм.

CSSMin изисква PHP >= 5.3.2 и PCRE; JShrink - PHP `^7.0|^8.0`. И двете са проверени
под PHP 7.4.33 и 8.2.34. Няма нови Composer или JavaScript runtime зависимости.
Копирани са само необходимите PHP файлове, лицензите и оригиналните `composer.json`
като метаданни. Тези директории не се използват като самостоятелни Composer пакети.
Namespace префиксите са `tubalmartin\CssMinV411` и `JShrinkV181`, за да няма конфликт
с други заредени версии. Освен префиксите са премахнати само интервалите върху празни
редове от upstream файловете; функционалният код е непроменен.

## Промени в поведението

CSSMin 4.1.1 запазва мерните единици при нулеви стойности, необходими например в
`--gap:0px`, `flex:0 0 0%` и времетраене `0s`. Включва поправки за `@import` адреси
с точка и запетая и по-новата обработка на CSS правила от upstream.
JShrink запазва интервалите в template literals и поддържа съвременни конструкции,
покрити от официалните му тестове. Изданието 1.8.1 обновява PHP матрицата в CI.
И двата адаптера запазват важните `/*! ... */` коментари.

В стария JS minifier проверката за край на входа вече не подава `null` към
`preg_match()`/`ord()` под PHP 8.2. Сравнените legacy изходи остават еднакви.
Hook-ът на `minify_Plugin` продължава да запазва оригиналния източник при exception.

## Проверки

От корена на хранилището:

```sh
php minify/tests/versions.php
php compactor/tests/bundles.php
php jquery/tests/loading.php
```

За официалните CSS/JS примери използвайте checkout на таговете, включително `tests/`
(JShrink release архивът изключва тестовете):

```sh
php minify/tests/upstream.php /path/to/cssmin-v4.1.1 /path/to/JShrink-v1.8.1
```

Проверени под PHP 7.4 и 8.2: 35 проверки на адаптерите и превключването в един процес;
87 официални примера (49 CSSMin, 24 JShrink, 14 Uglify от JShrink тестовете).
Изходът на JS адаптера се сравнява и побайтово с непроменения upstream клас.
Допълнително 8 целеви legacy изхода са сравнени побайтово с кода преди промяната.
Пълният CSS corpus със стария minifier не приключи в рамките на 60 секунди;
не се представя като преминала legacy проверка.

Браузърната проверка мина през стандартния SBF pipeline и compactor, под двата PHP
runtime-а, с цикъл нови -> стари -> нови настройки. За повторение в тестова
инсталация подайте през SBF два отделни JS файла: първи с `"use strict"`, template
literal с кирилица и два интервала, regex и присвояване без финална точка и запетая;
втори, започващ с IIFE, който показва стойностите в DOM. Очакват се запазени два
интервала, верен regex резултат, strict mode и едно изпълнение на втория файл.
За CSS използвайте `--gap:0px;width:calc(200px - var(--gap))`, рамка 1px и относителен
`url("icon.svg?v=1#mark")`. Очакваната външна ширина е 202px и изображението се зарежда.

С новите библиотеки проверените стойности са правилни. При legacy избора се запазват
досегашните ограничения: интервалите в template literal се свиват и единицата в CSS
променливата отпада. Това са различия между версиите, не обещание за еднакъв изход.

CSSMin е regex minifier, а JShrink не е пълен ECMAScript parser или transpiler.
Не се гарантира поддръжка на всички бъдещи CSS/JS конструкции. Тестът пропуска CSS
примера за опционално пренасяне на редове и групите `requests`/`development`, които
самият JShrink изключва в `phpunit.xml.dist`. Например Unicode whitespace примерът
в `requests` не съвпада с очакванията дори при непроменения upstream код.
