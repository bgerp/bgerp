# Sass / scssphp

## Версии и настройки

Глобалните defaults остават `SASS_USE_COMPOSER=no` (вграденият PHPSass) и
`SASS_VERSION=1.0.4` за избралите scssphp. Вграденият код в `sass/phpsass/` е
непроменен. Версията на bgERP setup остава `0.1`.

В настройките на пакета `sass` в `core_Packs` се избира PHPSass или scssphp чрез
Composer. Само при scssphp се показва версията: `1.0.4`, `1.13.0` или `2.1.0`. Скриването
на полето не изтрива избора. Записът инициализира пакета по стандартния начин.
За съществуваща инсталация без променена настройка не се избира нов компилатор.

Използва се съществуващият `core_Composer::install()`, в общия Composer проект.
Точната версия позволява връщане от 1.13.0 към 1.0.4. Не се създават отделни
Composer проекти, не се сменят функциите на `core_Composer`, не се добавят
библиотеки във Git. Изборът на PHPSass не инсталира и не премахва Composer пакети.
В общия vendor може да има само една активна версия на scssphp; връщането към
другата изисква успешна Composer инсталация и достъп до нейната дистрибуция.

Липсващата избрана версия се показва от `checkConfig()` по стандартния начин.
Адаптерът отказва новия режим при липсваща или различна заредена библиотека,
за да не запише CSS от друг компилатор в кеша на избраната версия. След отстраняване на
Composer проблем инициализирайте пакета `sass` отново.

## Upstream и зависимости

Към 2026-10-29 последната обща версия за PHP 7.4 и 8.2 е **1.13.0**.
Последната стабилна версия **2.1.0** изисква PHP 8.1+ и има промени в API след
пълно пренаписване на компилатора. Тя е добавена като изричен избор за съвместима PHP среда.

Спрямо 1.0.4 линията до 1.13.0 включва поправки за PHP 8.1/8.2, Unicode,
относителни imports, CSS променливи, цветови функции, селектори и media queries.
`compileFile()->getCss()` заменя остарелия `compile()` само в новия режим и
предава пътя на файла за относителните imports. Това не е промяна на дизайна
на интерфейса. Форматирането на генерирания CSS може да се различава.

1.13.0 изисква PHP >=5.6, `json`, `ctype` и на практика `mbstring` или `iconv`.
Няма други runtime Composer зависимости. Лицензът остава **MIT**; дистрибуцията
запазва upstream LICENSE. Адаптерът на bgERP остава GPL 3.

Официални източници:

- [1.13.0](https://github.com/scssphp/scssphp/releases/tag/v1.13.0)

## Кеш и съвместимост

Новият режим записва CSS само в SBF, със суфикс `_scssphp1_13_0.css` или `_scssphp2_1_0.css`.
Не презаписва CSS до SCSS източника. Така връщането към стария режим използва
досегашния CSS/SBF. Compactor получава различен SBF път и отделен сборен файл.
Промяна на SCSS в наблюдаваната директория сменя кеша по досегашния механизъм.
Imports извън нея не получават ново проследяване на зависимости.

Резервният PHPSass при грешка в компилацията е запазен, както и старите
параметри и обработката на изключения. `core_exception_Redirect` се предава
нагоре, а Composer таймерът се затваря и при изключение. Опцията `$style`
продължава да се прилага само в PHPSass, както преди тази промяна.

## Изолирани тестове

Изтеглете официалните версии 1.0.4 и 1.13.0 в отделни тестови директории
(с `scss.inc.php`), без да сменяте общия vendor. Изпълнете от корена на bgERP
под PHP 7.4 и PHP 8.2, с нова изходна директория за всеки тест:

```sh
php sass/tests/versions.php phpsass - /tmp/sass-test-phpsass
php sass/tests/versions.php 1.0.4 /path/to/scssphp-1.0.4 /tmp/sass-test-104
php sass/tests/versions.php 1.13.0 /path/to/scssphp-1.13.0 /tmp/sass-test-113
```

По желание подайте копие на `sass/Converter.class.php` от ревизията преди
промяната като пети аргумент само за PHPSass и 1.0.4. Тогава CSS се сравнява
байт по байт със стария адаптер. Не използвайте текущия адаптер за baseline.

Проверяват се defaults, setup диагностика, отказ при липсваща нова версия,
кирилица, суми, imports, mixins, цикли, скрити елементи, относителни изображения,
1000 CSS правила, невалиден mixin, кеш и превключване. JSON резултатът съдържа
броя проверки, CSS SHA-256, старите PHP deprecations и отчетените fallback-и.
Тестът не зарежда bgERP/базата, не извиква Composer и пише само в изходната папка.

Проверено на PHP 7.4.33 и 8.2.34: 18 проверки за PHPSass, 18 за 1.0.4 и 27
за 1.13.0, включително baseline сравнение за старите два режима. Новият режим
няма PHP warnings/deprecations в тестовете. 1.0.4 запазва съществуващите
PHP 8.2 deprecations. Неговият относителен import в теста използва досегашния
fallback; отделен пример без imports доказва и директната му компилация.

Допълнително 24 реални SCSS източника дават еднакъв CSS между двете PHP версии.
При първоначалния тест невалидният ред `$warningColor = #b75b00;` в
`css/common.scss` водеше до резервния PHPSass; поправката е описана по-долу. Примерите с `calc()`
в `css/twoColsFilter.scss` и `planning/tpl/TaskOrderReport.scss` се компилират
с новата версия; старите компилатори имат ограничения при тях.

## Браузърна проверка

1. Отворете генерирания `index.html` през тестов HTTP сървър. Сравнете трите
   режима: син текст, таблица с рамки и 8px padding, дясно подравнена сума
   `123,45 лв.`, квадратното изображение и липсата на скрития текст.
2. В тестова инсталация добавете синтетична страница, която включва fixture CSS
   през `ET::push(..., 'CSS')`. Проверете директно SBF и обединение с compactor.
3. Чрез `core_Packs` изберете 1.13.0, 1.0.4, PHPSass и отново 1.13.0. Проверете
   различния SBF суфикс, еднаквия изглед и непроменения стар CSS. Повторното
   зареждане трябва да използва кеша; промяна на SCSS трябва да го обнови.
4. Проверете зависимостите в общите composer.json/lock преди и след избора.
   В проведените тестове се променя само `scssphp/scssphp`; връщането към 1.0.4
   възстановява точно предишния lock. Проверени са и двата PHP уеб runtime-а.

Тестовете покриват изброените сценарии, а не всички частни теми и Sass конструкции.

## scssphp 2.1.0 / PHP 8.1+

[Официално издание](https://github.com/scssphp/scssphp/releases/tag/v2.1.0),
[manifest](https://github.com/scssphp/scssphp/blob/v2.1.0/composer.json).
Клонът 2.x е пренаписан по Dart Sass; 2.1.0 добавя поправки на `@extend`,
функции и съвместимост с PHP 8.5. MIT лицензът е запазен. Нужни са PHP >=8.1,
`ctype`, `json`, `mbstring`, `league/uri`, `league/uri-interfaces`,
`scssphp/source-span` и `symfony/filesystem` в ограниченията на manifest-а.
Адаптерът използва `compileFile()->getCss()` и при 2.1.0.

На PHP 7.4 записът на 2.1.0 се отказва със стандартна грешка към `SASS_VERSION`.
`checkConfig()`, инициализацията и конверторът също проверяват PHP преди Composer
или autoload. Неизползван избор на 2.1.0 не блокира PHPSass. При споделен vendor
между PHP 7.4 и 8.2 оставете 1.13.0: новите зависимости повишават минималния PHP
на целия Composer autoloader, включително за други пакети и CLI задачи.

Проверка на 2.1.0 с инсталираните зависимости в тестов Composer набор:

```sh
php sass/tests/versions.php 2.1.0 /path/to/vendor/autoload.php /tmp/sass-2
```

Резултати към 29.10.2026: тестът преминава под PHP 8.2.34 за кирилица, суми,
imports, стилове, скрити елементи, 1000 правила, грешен SCSS и отделен SBF кеш.
PHPSass, 1.0.4 и 1.13.0 преминават под PHP 7.4.33 и 8.2.34; CSS на старите режими
съвпада байт по байт с адаптера преди добавянето на 2.1.0.
От 24 проверени реални SCSS файла 21 се компилират директно с 2.1.0, а три
използват досегашния PHPSass fallback: `css/common.scss` (невалидна media query),
`css/new-design.scss` (`1top`) и `hr/tpl/style.scss` (`1border-collapse`).
Това са резултатите преди описаните по-долу поправки на `new-design.scss` и `common.scss`.
Примерът е проверен и в браузър с 2.1.0,
включително видима кирилица/сума и скрит елемент. В `core_Packs` под PHP 7.4
е проверен отказът и запазването на предишния избор.

## Регресии в new-design.scss

`new-design.scss` вече се компилира директно с 2.1.0, без PHPSass fallback.
Цветовите селектори за `span`, `li`, `.legend` и вложените връзки запазват
специфичността и реда на правилата. Премахнат е само неактивният блок с `1top`;
не се активират нови `top` отмествания. Така CSS променливите на градиента и
единиците `300ms` не минават през несъвместимия резервен компилатор.

Тестът компилира действителния източник през `sass_Converter` и `minify_Css`,
отказва всеки fallback и проверява 12-те цветови схеми, връзките, реда на
правилата и неактивните отмествания. По желание подайте SCSS от ревизията преди
поправката за сравнение на целия CSS. За 2.1 подайте получения предишен CSS от
1.13, защото старият SCSS не е валиден за 2.1:

```sh
php sass/tests/newDesign.php phpsass - /tmp/design-legacy /path/to/before.scss
php sass/tests/newDesign.php 1.0.4 /path/to/scssphp-1.0.4 /tmp/design-104 /path/to/before.scss
php sass/tests/newDesign.php 1.13.0 /path/to/scssphp-1.13.0 /tmp/design-113 /path/to/before.scss
php sass/tests/newDesign.php 2.1.0 /path/to/vendor/autoload.php /tmp/design-21 /tmp/design-113/before.css
```

Сравнението изключва точно стария невалиден блок. Допуска се само еквивалентното
подреждане на селекторите в една група при PHPSass и незадължителните кавички
около простите стойности на CSS атрибути. Другите декларации и редът на правилата
трябва да съвпадат. Старите компилатори са проверени под PHP 7.4 и 8.2; 2.1 е
проверен под PHP 8.2. Съществуващите deprecations на 1.0.4 се броят отделно.

Сервирайте изходната директория през изолиран HTTP сървър и отворете `index.html`.
Тя сравнява `before.css` и `new-design.css` при ширини 360, 1024 и 1440px,
включително положителни и отрицателни случаи за селекторите. Очаква се `PASS`
без разлики. Параметрите `?before=...&css=...` позволяват същата проверка срещу
SBF или compactor URL от тестовата инсталация.

Допълнително е проверено с реален HAProxy 3.0.30, Apache и scssphp 2.1.0:
нормален SBF запис, отказан запис, SASS само в compactor конфигурацията и
изрично заявен SASS, възстановяване на изтрити копия/сборни файлове, gzip/HEAD,
кеширане и ограничаване на истински 404. При повторение използвайте изолирани
източници и кеш директории. Проверете еднакви CSS байтове в двата compactor
случая, `no-cache` за CSS от паметта и HTTP 200 без натрупване на 404 при
възстановяване. Продукционните HAProxy правила и частните теми не са обхванати.

## Регресии в common.scss

`common.scss` се компилира директно с scssphp 1.0.4, 1.13.0 и 2.1.0, както и
с PHPSass. Поправени са присвояванията с `=`, вложените type селектори и
невалидната media query. Невалидният втори `@media` клон е премахнат, без да се
активира преди неработещото условие за `-ms-high-contrast: active`.

Запазено е реалното поведение на досегашния PHPSass CSS: `&input` означава
клас `.flashEleminput`, а не `input.flashElem`; маркирането остава моментно,
разстоянието между буквите в `.trip-type` остава 0, а правилото за курсора
запазва специфичността си. Цветовете и размерите на трите вида потвърждения
не се променят. Изборът на компилатор и runtime PHP кодът остават същите.

Запазете CSS от ревизията преди поправката за браузърното сравнение. Във всички
предишни scssphp режими `common.scss` използваше PHPSass fallback, затова
baseline трябва да е реалният му краен CSS, а не неуспешен директен compile.
Тестът не допуска fallback за текущия източник:

```sh
php sass/tests/common.php phpsass - /tmp/common-legacy /path/to/before.css
php sass/tests/common.php 1.0.4 /path/to/scssphp-1.0.4 /tmp/common-104 /path/to/before.css
php sass/tests/common.php 1.13.0 /path/to/scssphp-1.13.0 /tmp/common-113 /path/to/before.css
php sass/tests/common.php 2.1.0 /path/to/vendor/autoload.php /tmp/common-21 /path/to/before.css
```

Първите три режима се проверяват под PHP 7.4 и 8.2, а 2.1 изисква PHP 8.1+.
`compiler.inc.php` е общата изолирана среда за този тест и `newDesign.php`.

Сервирайте резултатите през тестов HTTP сървър и отворете `index.html`.
Осигурете и изображенията от `img/` по относителните CSS пътища. Страницата
сравнява целия CSSOM, включително реда, селекторите и декларациите, както и
изчислените стилове на формите, маркирането, пътните листове и потвържденията
при 360, 1024 и 1440px. Нормализират се само еквивалентни цветови записи,
подредбата на селекторите в една група и неактивното `not all` условие.
Очаква се `PASS` с празен списък на разликите. Променени `500ms` и `0.5px`
стойности се откриват от теста. CSSOM покритието зависи от браузъра.

За SBF/compactor сравнение подайте `?before=...&css=...`. Baseline и текущият
CSS трябва да разрешават относителните изображения до едни и същи URL-и.
Проверено е през изолиран HAProxy 3.0.30 с реален scssphp 2.1.0: 100 предишни
HTTP сценария и 38 проверки с общ `common` + `new-design` сборен файл,
включително двата compactor случая, отказан SBF запис и възстановяване от паметта.
Не са проверявани продукционната HAProxy конфигурация и всички частни теми.
